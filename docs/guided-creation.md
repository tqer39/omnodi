# 質問から作る雛形と処理の流れの説明

## 新しく作る

上部の「新しく作る」を押すと、「何を作る予定ですか？」から始まる短い質問を表示します。
答えるたびに次へ進み、「戻る」で前の質問、`Esc` や「キャンセル」で図を変えずに閉じます。
最後の確認画面に回答・作成する要素・処理の流れ・設計上の仮定・確認が必要な事項を表示します。
各回答の「変更」で質問へ戻り、「確認へ戻る」で確認画面へ戻れます。

| 質問         | 選択肢                                                                            |
| ------------ | --------------------------------------------------------------------------------- |
| 作るもの     | API サーバー、Web アプリ（画面＋API）、静的サイト、非同期処理（キュー＋ワーカー） |
| クラウド     | AWS、Google Cloud、Azure                                                          |
| リージョン   | 東京（東日本）だけ、大阪（西日本）だけ、両方（2つ目は保存データの複製先だけ）     |
| 実行方式     | クラウドで描けるものだけ（AWS は ECS Fargate・Lambda・EC2 など）                  |
| データの保存 | SQL、キーで読み書きするデータ、ファイル（複数選択）、保存しない                   |
| 配備の流れ   | GitHub Actions から OIDC で配備する流れを描くか                                   |

静的サイトは実行方式とデータの保存を質問しません。
Google Cloud は関数の実行方式を選択肢に出しません。選べない回答は、選べる値に寄せて確認画面に表示します。

### 生成の規則

生成は `src/core/blueprint.ts` の決定的な規則だけで行います。LLM・認証・クラウド API・通信を使わず、
単一 HTML でもオフラインで動作します。同じ回答からは常に同じ DSL を作ります。
作った図は `validateDiagram`・`serializeDSL`・`parseDSL` を通し、DSL エディター・保存・Undo と同じ表現にします。

例えば AWS・API サーバー・東京だけ・SQL では、1つのリージョン `ap-northeast-1` に
VPC・2つの AZ の Public／Private Subnet・ALB・ECS・RDS を置き、利用者のアプリから順に結びます。
保存方式で保存先の種類と処理の終点が変わり、用途で入口・キュー・静的ファイルの有無が変わります。
接続には `route`・`step`・`purpose`・`description` を付け、説明モードの順序と文章に使います。

ALB の Lambda ターゲットは待受ポートへの通信として描かず、JSON イベントによる関数呼び出しとして説明します
（[AWS 公式の Lambda ターゲット仕様](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/lambda-functions.html)）。
VPC の Internet Gateway・NAT Gateway・VPC エンドポイントなどの外向き経路は未設計として残します。

アカウント ID・プロジェクト ID は推測せず、未指定として `unresolved` に残します。
CIDR・AZ は設計用の仮の値で、証明書・台数・バックアップ方式なども確認が必要な事項として残します。
図には「この図について」の注記を置き、構築済み・通信や権限の検証済みと誤解されないようにします。

### 下書きと履歴の保護

DSL エディターに解析していない下書きがある場合は作成できません。確認画面に理由を表示し、下書きを保持します。
作成は通常の図の読み込みと同じ履歴に入り、「元に戻す」で作成前の図へ、「やり直す」で雛形へ戻せます。
作成時は 3D に切り替わります。表示方式は履歴に含まれず、Undo/Redo 後も現在の 2D/3D を維持します。
3D の初期表示は、全体または境界・立体・名札が読める倍率（0.9 倍以上）で収まる場合はそれを表示します。
収まらない大きな図では、床下の通信・複製・切替（監視信号を除く）でつながる立体を注目領域とし、
画面の中央に大きく収めます。台座上に配置された端点を優先するため、AWS の API の例では ALB・ECS・RDS を表示し、
離れた GitHub の配備経路や利用者は「全体」ボタンで確認します。注目領域が画面より広い場合も 0.6 倍より縮小せず、
注目領域の中央に最も近い端点の立体を画面の中央に置きます（端点の間の空白を中央にしません）。
注目領域と構造全体の広さが近く、構造全体が 0.6 倍以上で収まる場合は、縮小への後退を避けて構造全体を表示します。
通信経路でつながる立体がない図では、読める倍率で、図の左上に最も近い見出しか立体から表示します。
投影した図の外接矩形の左上が空白でも、初期表示に実際の要素が入ります。

## 処理の流れの説明

図の操作にある「処理の流れ」を押すと、接続を1ステップずつ説明するパネルを開きます。
2D・3D のどちらでも使え、現在のステップの接続と両端を強調し、矢印の向きに粒子を流します。
3D では曲線・床下の通信・上空の認証やデプロイの配管にも沿って流します。

| 操作           | 内容                                                 |
| -------------- | ---------------------------------------------------- |
| 再生・一時停止 | 自動で次のステップへ進める・止める（`Space`）        |
| 前へ・次へ     | 1ステップ戻る・進む（`←`・`→`）                      |
| ステップへ移動 | 一覧から任意のステップへ移る                         |
| 画面に表示     | 押したときだけ、接続の両端が見える位置へ画面を動かす |
| 終了           | 説明を閉じて強調を消す（`Esc`）                      |

キーボード操作は説明パネル内にフォーカスがあるときに使えます。

順序は DSL の `route`・`step`・`routeDirection` を優先します。経路は図に現れた順に、往路の後に復路を並べます。
順序の指定がない接続は、通信・業務フローを先に、依存・認証・デプロイ・監視信号を後に、
外部の利用者や入力のない要素から辿れる順で並べます。どちらも図の意味に沿った説明であり、
観測した実行順や通信の成立を示すものではありません。パネルにも順序の根拠を表示します。

折りたたみや表示オプションで線が隠れても説明は続け、「折りたたみを開いて表示」で祖先の境界を展開できます。
属性編集など図の中での操作では、同じ接続が残っていれば説明を続け、説明中の接続がなくなると終了します。
DSL の「解析して反映」、別の図の読み込み、履歴で別の図へ戻った場合は説明を終えます。
「折りたたみを開いて表示」は必要に応じて詳細範囲を解除しますが、パン・ズームを保持します。
「画面に表示」を押したときだけ視点を移動します。OS の「視差効果を減らす」設定では自動再生せず、粒子を止めて表示します。
この設定では前へ・次へで手動で進め、再生中に設定を有効にした場合も停止します。
タブが非表示になると再生を止めます。ステップの文章はスクリーンリーダーへ読み上げ領域として通知します。

## 3D の公式ロゴと Octocat

3D 表示では、同梱した AWS の公式サービス・リソースアイコンを持つ要素を、厚みと面取りのある板に載せます。
板の側面には各アイコンの公式色を使い、正面にはアイコンを原形・公式色のまま置きます。
正面は常に画面と平行な正方形になる寸法にし、ロゴ自体を押し出し・変形・回転・反転しません。
公式色の対応は `src/assets/aws-icon-colors.ts` にあり、単体テストで同梱 SVG の色と一致することを確認します。
境界を表すグループアイコンと、Google Cloud・Azure のアイコンは従来の機能別の立体のままです。

GitHub の要素（`saas.github`、`github.repository`、`github.actions` と、表示アイコンにこれらを指定した要素）は、
コードで組み立てた Octocat の立体で表します。猫耳・頭・顔・胴・5本の触手を持ち、回転に合わせて陰影が変わります。
ポインターを向けるか選択すると触手を上げて手を振り、クリックすると一度だけ跳ねます。常時のアニメーションはありません。
名札には要素の名前と GitHub の種別を表示し、Omnodi 自体のマスコットとしては使いません。
Octocat は利用者から利用許諾がある旨の明示を受けて実装しています。別の利用者・用途では GitHub の条件を確認してください。
